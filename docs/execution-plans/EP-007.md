## Outcome
Introduce the immutable ActionPlan pipeline and deterministic recovery (ARCH §8.3–8.5), strictly
behind the TEST-STRATEGY gates. No destructive filesystem capability becomes reachable until the
"First mutation preview" exit criteria pass in the sandbox.

## Directive reconciliation (source-of-truth order, AGENTS §2)
TASK-FILEOS-007 ranks below the safety docs, so four points are narrowed:

- **"2-Phase Atomic Swap for all moves"** → atomic swap is same-volume rename ONLY; cross-volume is
  copy → verify → promote → retire (SI-003, ADR-006).
- **"Panic Safe → rollback"** → rollback is typed-error-driven; panic/unwrap on runtime paths is
  forbidden (AGENTS §8, SI-005).
- **"LIFO journal replay undo"** → Undo is a NEW planned, revalidated operation (SI-008); LIFO
  ordering is acceptable, blind reversal is not.
- **Target crates corrected**: planner/executor/journal are their OWN crates (ARCH §4), NOT
  `fileos-app` as the directive assumed.

## Scope
- **Slice A (this PR):** immutable ActionPlan domain types, UUIDv7 `ActionId`, content-addressed
  plan fingerprint, `action-plan-v1` JSON export, unit + property tests. Pure domain, ZERO I/O →
  compliant with the Sprint 0 read-only foundation.
- **B/C/D:** sequenced behind gates, NOT in this slice.

## Non-scope
Any real move/rename/delete/quarantine; executor/journal runtime; BLAKE3/SHA wiring; AI (SI-012
advisory only).

## Sequencing & gates
1. **A** — ActionPlan domain (this PR). Gate: unit + property green, no I/O reachable.
2. **Planning preview** — planner crate; protected-zone + stale rejection (SI-006, SI-011).
3. **B** — Approval contract: fingerprint verify, INVALIDATE on hash/mtime drift (SI-006).
4. **C** — Executor: same-volume state machine first (SAFETY §4.1); journal-precedes-mutation
   (SI-014); truthful success (SI-005). Cross-volume per ADR-006. Gate: "First mutation preview".
5. **D** — Undo as a new planned op, verified restore (SI-008). Gate: crash checkpoint matrix.

## Acceptance criteria (slice A only)
- ActionPlan is immutable after construction; edits produce a new value + new fingerprint.
- Every action carries a UUIDv7 (version 7, variant 0b10), kind, source, destination, and expected
  checksum where content certainty is required (StageForDeletion mandatory).
- Plan-level validation rejects: duplicate destination, duplicate source, an action whose source is
  another action's destination, and move-into-own-descendant.
- Deterministic: identical inputs ⇒ identical canonical JSON ⇒ identical fingerprint.
